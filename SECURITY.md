# Security Policy

## Supported versions

Security fixes are applied to the latest code on the default branch while the project remains pre-1.0.

## Report a vulnerability

Do not open a public issue for a suspected vulnerability or exposed secret. Use GitHub's private vulnerability reporting feature for this repository. Include the affected version, reproduction steps, impact, and any suggested mitigation.

Never include live credentials, private endpoints, personal data, or proprietary source material in a report fixture.

## Scope

These projects are local-first MVPs. Their READMEs and safety documents state the current trust boundaries. A documented non-goal is not automatically a vulnerability, but boundary bypasses, unsafe path handling, replay problems, and secret exposure are in scope.
